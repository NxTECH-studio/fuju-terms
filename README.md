# fuju 規約・ポリシー

本リポジトリは、独自通貨「fuju」を用いたサービス全般（以下「本サービス」）における利用規約およびプライバシーポリシーを管理します。

## プロジェクトの性質（重要）

本サービスは、**学生ハッカソン規模のプロトタイプ**として、**個人または少人数のチーム**によって運営される**非営利・非法人**のプロジェクトです。運営主体として法人は存在しません。

本サービスは、Netflix映画『**超かぐや姫！**』（© コロリド・ツインエンジンパートナーズ）に**着想を得た**プロジェクトであり、同作の**二次創作物そのものではない**ことを意図しています。本サービスの名称、アプリ内の画像・映像・音声・テキスト等のコンテンツには、原作の著作物（原作に登場するキャラクター、原作の映像・音源、原作のロゴ等）を直接使用しないことを原則とします。

一方で、本サービスのテーマ・世界観は原作から着想を得ているため、運営チームは原作への敬意を表し、[『超かぐや姫！』二次創作ガイドライン](https://www.cho-kaguyahime.com/special/detail.html?id=1024)（以下「**原作ガイドライン**」といいます。）の趣旨を尊重し、同ガイドラインに抵触する運用を行わないよう努めます。同ガイドラインが改定された場合も同様に尊重します。

本サービスは、原作の権利者および制作委員会による**公式のサービスではなく**、公式から許可、推奨、提携、協賛、監修を受けたものでもありません。ユーザーおよび第三者は、本サービスを公式サービスと誤認させる態様で利用・紹介してはなりません。

## 運用方針

- 本リポジトリで管理する文書が、fujuプロジェクトにおける利用規約・プライバシーポリシーの原本となります。
- 改定は Pull Request ベースで行い、マージ時点のコミットを「施行バージョン」として取り扱います（後述の自動タグ付け参照）。
- 感情推定や生体情報（表情・音声）の取扱いに関わる変更は、ユーザーへの再同意取得の要否を必ず検討してください。
- 原作ガイドラインの更新有無は CI で自動監視していますが、Issueが起票されたら速やかにレビューしてください。
- 重要な変更があった場合は、各ドキュメントの末尾にある「改定履歴」を必ず更新してください（CIで更新漏れを検知します）。

## CI / CD

GitHub Actions で以下を自動化しています。

### PR検証 (`.github/workflows/validate.yml`)

プルリクエスト時に以下を並列実行します。いずれかが失敗した PR はマージをブロックする運用を推奨します。

| ジョブ | 内容 | 使用ツール |
| --- | --- | --- |
| `markdown-lint` | Markdown のフォーマット検証 | markdownlint-cli2 (`.markdownlint.yaml`) |
| `link-check` | 全ドキュメントのリンク切れ検出 | lychee (`.lycheeignore`) |
| `placeholder-check` | `{{...}}` プレースホルダーが README 一覧と整合しているか | `scripts/check-placeholders.sh` |
| `article-check` | 条文番号（第N条）の連続性と同一ファイル内の相互参照整合性 | `scripts/check_articles.py` |
| `revision-history` | 本文変更時に「改定履歴」への追記があるか | `scripts/check-revision-history.sh` |

### 原作ガイドライン監視 (`.github/workflows/monitor-guideline.yml`)

毎日 JST 10:00 に原作ガイドラインページを Playwright で取得・正規化し、ハッシュを `.guideline-monitor/current.sha256` と比較します。変更を検知した場合、自動で Issue を起票し、レビュー用チェックリストを提示します。変更後のスナップショットは同ディレクトリに自動コミットされます。

### 施行タグ自動作成 (`.github/workflows/release-on-merge.yml`)

`main`（または `master`）へ規約ファイル（`terms.md` `privacy.md` `auth-component.md` `README.md`）の変更がマージされると、`enforced-YYYYMMDD` 形式のタグと GitHub Release を自動作成します。同日複数マージ時は `-2`, `-3` のサフィックスが付与されます。リリースノートには前施行バージョンからの差分と関連コミットを含めます。

## プレースホルダー

ひな形には以下のプレースホルダーが含まれています。公開前に実際の値へ置き換えてください（個人・チーム運営のため、法人前提の項目は不要であれば削除・統合してください）。

- `{{運営チーム名}}` — プロジェクトを運営する個人名またはチーム名（例: "fuju開発チーム"）
- `{{連絡窓口}}` — 問い合わせ用の連絡先（メールアドレス、Issue URL、フォームURL等）
- `{{準拠法の国}}` — 準拠法（例: 日本）
- `{{施行日}}` — ドキュメントの施行日（YYYY-MM-DD）

> **注記**: ハッカソン規模・非法人での運用を前提としているため、本ひな形では法人向けの「所在地」「代表者名」「専属的合意管轄裁判所」を必須項目から外しています。将来、正式な法人化・商用化を行う場合には、所在地・代表者・管轄裁判所を明示する条項を追加してください。
